# Contributing

## Workflow

1. Create a focused feature branch from `main`.
2. Keep `.codex`, `.openai`, secrets, and local environment files out of commits.
3. Make small commits grouped by engineering concern.
4. Run formatting, lint, unit tests, browser tests, and the production build.
5. Open a pull request describing behaviour, validation, and deployment considerations.

## Content standards

Use specific industrial language. Do not add unverifiable customer numbers, certifications, testimonials, performance percentages, client logos, or case studies. Label illustrative and simulated material clearly.

## Code standards

Keep brand values in `src/config/site.ts`, reusable copy in content modules, and shared behaviours in accessible components. Preserve keyboard operation, visible focus, semantic HTML, reduced-motion support, and responsive behaviour from 320px upward.
